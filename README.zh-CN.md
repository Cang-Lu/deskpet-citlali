# 茜特菈莉 · 桌面宠物

[English](README.md) · **简体中文**

一个**独立运行**的桌面宠物，支持 Windows / macOS / Linux。它不运行在 DeepSeek Harness、Codex 或任何 agent 宿主里——它就是一个应用。

- 主角是《原神》的**茜特菈莉**，使用社区精灵图素材（见[素材与许可](#素材与许可)）。
- 通过 **DeepSeek API** 对话，回复以气泡形式显示在她头顶。
- 一套**状态机**驱动动画与粒子特效：待机、思考、说话、开心、失落、打瞌睡、走动、看书……
- 她有自己的**脾气**：先找地方定居，换几个姿势，溜达到新位置，路上还会自言自语。
- **鼠标靠近**她会坐起来看着你，用的是图集里那 16 个视线方向。

---

## 快速开始

需要 **Node.js 20 或更高版本**（开发时用的是 Node 24）。

```bash
npm install
npm start
```

首次运行她会打个招呼，并提示你还没有配置 API Key。**右键桌宠**（或右键托盘图标）→ **设置…**，把 Key 填进去即可。

### 直接下载 Windows 可执行文件

到 [Releases](../../releases) 页面下载，**不需要装 Node.js**：

| 文件 | 说明 |
| --- | --- |
| `Citlali-Setup-x.y.z.exe` | 安装版。可以选安装目录，会创建开始菜单和桌面快捷方式。 |
| `Citlali-Portable-x.y.z.exe` | 免安装单文件版。双击就能跑。 |

两个都是自包含的，约 90MB（这是 Electron 的底噪，不是应用本身的体积）。

> 构建产物**没有代码签名**，所以 Windows SmartScreen 首次运行会拦截。选「更多信息」→「仍要运行」，或者自己从源码构建。

### 自己构建 exe

```bash
npm install
npm run dist            # 安装版 + 免安装版，输出到 dist/
npm run dist:installer  # 只做安装版
npm run dist:portable   # 只做免安装版
npm run dist:dir        # 只出解包目录；最快，不用下载 NSIS
```

打包配置里有三处是刻意的：

- **关掉了 `npmRebuild`。** 这个项目没有任何原生依赖，重建步骤只会要求一套它根本不需要的工具链。
- **渲染层走 `fs` 读取，而不是 `net.fetch`。** 打包进 `app.asar` 后只有 Electron 的 `fs` 认识 asar 路径；把 `file:` URL 交给文件加载器会 404，结果是图集加载失败、窗口一片空白。
- **`build/icon.png` 是生成的**，不是手绘的：`npm run slice` 会从精灵图裁出 256×256，交给 electron-builder 转成 `.ico`。

### 如果 `npm install` 在 Electron 的 postinstall 步骤失败

个别受限环境（沙箱、某些企业安全策略）不允许安装脚本派生子进程。绕过办法是自己下载 Electron 二进制：

```bash
npm install --ignore-scripts
node tools/install-electron.mjs          # 打印出 ZIP= 和 DEST= 两行
# 然后解压 ZIP 到 DEST，并把 "electron.exe" 写进 node_modules/electron/path.txt
```

### 获取 DeepSeek API Key

到 <https://platform.deepseek.com> 注册并创建 Key（形如 `sk-…`），填进设置。点「测试连接」可以立即验证。

Key 通过 Electron 的 `safeStorage` 用系统密钥库（Windows 上是 DPAPI）**加密后**保存，并且**永远不会传给渲染进程**——设置界面只显示「已保存」，不回显明文。

> 填完记得点输入框右边的**「保存」**（按回车、或点「完成」也会保存）。保存后提示会变成「已保存，并使用系统密钥库加密存储」。

### 用的什么模型

默认 **`deepseek-chat`**（DeepSeek V3 非思考模式），接口 `https://api.deepseek.com`。模型名和接口地址都可以改，兼容任何 OpenAI 协议的服务。

## 工作模式：让她认真回答

默认状态下她把回复压在 **1~3 句、60 字以内**。这是人设里的硬约束——适合桌宠，但你真要问点正事时就不够用。

打开**工作模式**后：

- **解除长度限制**，允许长篇、Markdown（标题/列表/表格）和完整可运行的代码块
- **准确性优先于可爱**：不确定会直说，信息不足会先问，不编造 API 和参数
- 复杂问题先给结论或可执行步骤，再补解释
- 角色语气保留，但口癖收敛成偶尔一句，不影响信息密度
- **闲聊时依然是原来的语气**——主动搭话和打招呼不会突然变成说明书

| | 闲聊模式 | 工作模式 |
| --- | --- | --- |
| 温度 | 1.15 | 0.6 |
| 回复上限 | 700 tokens | 2400 tokens |
| 气泡高度 | 172px | 320px（窗口自动变高） |

**三种切换方式：**

- 在对话里输入 **`/work`** 进入、**`/pet`** 退出（也认 `/工作`、`/闲聊`）。这两种命令**本地处理，不消耗请求**。
- 托盘 / 右键菜单 → **工作模式**
- 设置 → 模型 → 工作模式

输入框提示文字和气泡边框会跟着变，不会搞不清当前在哪个模式。

## 怎么玩

| 操作 | 效果 |
| --- | --- |
| 左键单击她 | 打开输入框（`Enter` 发送，`Esc` 收起） |
| 按住拖动 | 把她搬到屏幕任意位置，位置会被记住 |
| **`Ctrl` + 滚轮** | **就地放大 / 缩小她** |
| 右键她 / 右键托盘图标 | 菜单：大小、显示隐藏、设置、置顶、穿透、开机自启、自主行为、查询余额、退出 |
| `Ctrl+Enter` | 在任意时刻唤出输入框（窗口有焦点时） |
| 把鼠标移近她 | 她放下小说坐起来看你；离开约 300px 就回去看书 |

气泡里的文字可以选中复制。**每句话都会自动隐藏**，不会一直挡着屏幕——短句 5 秒。想再看一眼，点她一下就会把最后一句调回来。对话记忆保存在本地，托盘菜单和设置页都能清空。

### 长回答会被保护

这里踩过坑，所以现在是明确的：

| 场景 | 行为 |
| --- | --- |
| 回答停留多久 | 随内容变长：7 秒起，每字 +90ms，最长 60 秒 |
| 你还没读完 | 她**原地不动、不吭声**，直到气泡收起（最长 25 秒） |
| 她的自言自语 | 回答在屏幕上时**直接跳过**，绝不会盖掉你正在看的内容 |
| 回答被关掉了 | 点她一下就能**原样调回来**；回答和闲聊分开保存，闲聊顶不掉回答 |
| 想看更早的 | 托盘 / 右键菜单 → **对话记录…** |

原来的问题是三个缺陷叠在一起：气泡一律 5 秒隐藏、自言自语复用了同一个气泡（还顺手覆盖了唯一的一份存档）、行为引擎完全不知道有人在看东西。

## 调整大小与画质

### 大小：无级可调

- **`Ctrl` + 滚轮**：鼠标放在她身上滚，每次 16px。
- **设置 → 外观与窗口 → 大小**：96–900px 滑块，1px 一档。
- **托盘 / 右键菜单 → 大小**：小/中/大/很大，以及 ±8px / ±32px 微调。

改完立即生效，没有被吸附到固定档位。

### 渲染方式

| 模式 | 行为 | 什么时候用 |
| --- | --- | --- |
| **超采样自适应**（默认） | 按整数倍把这一帧超采样到离屏缓冲，再缩放到你要的尺寸 | 默认就用它。任意尺寸都清晰 |
| **硬边像素** | 不做任何平滑，直接最近邻放大 | 想要那种锯齿分明的复古像素感 |

为什么默认模式能做到"任意尺寸都清晰"：先把精灵在离屏画布上按**整数倍**栅格化（这一步是最近邻，所以保持锐利），再把这块缓冲缩放到目标尺寸。目标是整数倍时最后一步就是 1:1 搬运，**像素级精确**；不是整数倍时是**降采样**而不是拉伸，所以边缘平滑而不是长满锯齿。缓冲按「帧 + 倍率」缓存，每帧只多一次 `drawImage`。

（早期版本是把尺寸吸附到整数倍，所以拖滑块会长时间没反应然后突跳。现在没有这个问题了。）

### 去边缘灰边

源美术在被抠出 alpha 之前是垫在深色背景上的，所以抗锯齿边缘像素的 RGB 是暗的。在**浅色桌面**上叠加时，这些像素会合成出一圈脏灰的描边——看起来就像角色整体发虚。

「去除边缘灰边」默认开启：启动时扫描图集，把非全不透明像素的 RGB 替换成邻近实体像素的颜色，**alpha 完全不动**。实测整张 1536×2288 图集重绘约 13 万个边缘像素，耗时约 130ms，只在启动时做一次。

想对比效果可以关掉它，用 `npm run slice` 生成 `.qa/fringe-proof.png`（原始）和 `.qa/fringe-after.png`（处理后）——都是白/黑/洋红/深色四种底色上的同一块角色，灰边在白底上最明显。

### 关于状态色调

情绪色调（开心偏暖、难过偏冷、恼火偏红……）**默认关闭**，可以在设置里打开。

关掉是有依据的，不是口味问题：她的坐垫是一大片接近纯白的平面，所以**即使只有 0.13 的不透明度，蓝通道也会偏移约 11/255**——肉眼看就是"坐垫变成奶油色了"，也就是**角色被重新上色**而不是"被光照着"。情绪由粒子特效承担（星光、雨滴、怒气、飘 `z`、思考光点），它们完全不碰她的配色。

打开时它会被**裁剪在角色轮廓内**（绘制时用 `source-atop` 只作用在她身上），不会溢出到周围——不透明度再低也不会出现背景灰雾。

这条路径踩过三次坑，都记在下面：

1. **第一版用 `lighter` 在角色身后画了一个几乎铺满窗口的径向光晕。** 深色桌面上是若隐若现的氛围光，**浅色桌面上就变成一大片灰雾**——实测光晕中心把 255 的白底压到 231，看起来就像窗口背景坏了。
2. **改成裁剪进轮廓时，顺手把不透明度从 0.26 提到了 0.42。** 叠加混合下 0.42 是柔光，普通混合下 0.42 就是**重新上色**：白发变奶油、皮肤变金黄。
3. **降到 0.13 之后仍然偏黄。** 用程序量了真实截图才确认：坐垫区域 `b-r = -12`，在这么大一片平色上肉眼可见。于是干脆改成默认关闭。

连"改了默认值但对老用户无效"这个经典坑也记在这里：

> `deepMerge(DEFAULT_SETTINGS, stored)` 会用**存储的值**覆盖默认值。所以把 `moodTint` 的默认值从 `true` 改成 `false`，对**任何已经存过这个键的配置完全无效**——而这正是当时发生的事：代码是对的，但你的 `settings.json` 里还留着 `moodTint: true`。
>
> 修复方式是在配置里加 `settingsVersion` 并在加载时做迁移。有个额外的坑：迁移必须在 `deepMerge` **之后**运行，但版本号必须从**原始文件**读——因为 `deepMerge` 会把今天的默认版本号也填进去，合并之后就再也看不出配置是旧的了。

## 账户余额

接的是 DeepSeek 官方的 [`GET /user/balance`](https://api-docs.deepseek.com/api/get-user-balance/) 接口。

- **按需查询**：托盘 / 右键菜单 →「查询余额」，或设置页的按钮。菜单里也会显示上次查到的余额。
- **定时查询**：设置页里开关，间隔可调（默认 30 分钟）。启动后约 6 秒会查一次。
- **余额不足提醒**：低于你设的阈值（默认 ¥5）时，她会弹一个**置顶不易消失**的气泡提醒你去充值，托盘菜单也会标注「偏低，建议充值」。同一个金额 12 小时内只提醒一次。

赠金和充值余额在接口返回时会一并显示。提醒用的是**本地台词**——余额都快没了还花 token 去生成提示语，那就本末倒置了。

`is_available: false`（余额不足以调用 API）会单独标出来。

## 状态与动画对照

精灵图共 11 行：第 0–8 行是标准动作，第 9–10 行是 16 个视线方向。

| 状态 | 精灵行 | 触发时机 | 特效 |
| --- | --- | --- | --- |
| 趴着看书 | 0 | 定居姿势之一（权重最高） | — |
| 趴着发呆 | 7 | 定居姿势之一 | — |
| 趴着放空 | 0（更慢） | 定居姿势之一 | — |
| 坐着歇着 | 5 | 定居姿势之一 | — |
| 坐着张望 | 8 | 定居姿势之一，**最多 7 秒** | — |
| 坐着打瞌睡 | 6 | 定居姿势之一，**最多 5 秒** | 飘 `z` |
| 睡着 | 0（最慢） | 超过设定时长无人互动 | 飘 `z` |
| 走动 | 1 / 2 | 换 2–4 个姿势之后 | — |
| 思考 | 7 | 消息已发出，等模型回复 | 冰蓝光晕 |
| 开心 / 兴奋 | 4 | 模型返回 `happy` / `excited` | 金色星光 |
| 打招呼 / 害羞 | 3 | 启动问候、点击她 | 星光 / 粉色 |
| 失落 / 恼火 | 5 | 出错、`sad` / `angry` | 雨滴 / 怒气 |
| 视线跟随 | 9 / 10 | 鼠标靠近时 | — |

**剪辑名是按画面内容起的，不是按行名**——行名会骗人（见下）。完整动画总览见 [`docs/animations.png`](docs/animations.png)。

### 她闲着的时候会做什么

行为模型很简单，和真实桌宠的观感一致：

> **在某个地方定居 → 随机切换几个姿势 → 慢慢走到新地方 → 继续定居**

**定居阶段**会从下面这些姿势里随机挑，同一个姿势不会连着出现两次：

| 姿势 | 精灵行 | 停留 |
| --- | --- | --- |
| 趴着看书 | 0 趴着看书 | 12–26 秒 |
| 趴着发呆 | 7 趴着看书（另一套动画） | 8–18 秒 |
| 趴着放空 | 0（更慢） | 7–16 秒 |
| 坐起来歇着 | 5 坐着低头 | 5–9 秒 |
| 坐着左右张望 | 8 坐着摇头 | 4–7 秒 |
| 坐着打瞌睡 | 6 坐着点头 | 3–5 秒 |

趴着和坐着大约是 **53% / 47%** 的配比，所以她会反复换姿势，而不是一直趴着。

**走动是独立的一段**，不是随机姿势之一：因为这张图集的走路美术**本身就是"坐着摇摆"**，站着不动播它看起来就是在原地走。每换 **2–4 个姿势**她就起身走一段（130–260px，约 **2.2–4.5 秒**，58px/s，动画 8fps），到了之后重新开始定居。

> 之前这里是 130px/s + 12fps（"看着非常着急"就是这个）；再之前我用第 1 行当坐姿，于是"像走路但没走路"——那行是走路的美术。

另外还有：

- **12 分钟没人理 → 打瞌睡**（`z` 粒子飘出来），你回来时她会惊讶一下
- **鼠标靠近 → 坐起来看你**，视线跟着鼠标转，离开约 300px 就回去
- **每 25 分钟**（可设）调用一次 DeepSeek 主动找你搭话

### 她说的话永远和当前动作匹配

**每一句台词都挂在姿势上**，不是共用一个池子——所以"明明醒着却说好困"这类错位在结构上就不可能发生：

| 姿势 | 台词池 |
| --- | --- |
| 趴着看书 | 看书相关：「别吵，正到精彩的地方。」 |
| 趴着发呆 | 闲聊：「你桌上那杯水，凉了吧。」 |
| 坐着张望 | 「……嗯？」「好像有动静。」 |
| 坐着打瞌睡 | **只有这个姿势**会说困话：「再看一页就睡……就一页。」 |
| 坐着低头 | 「……在想事情。」「让我静静。」 |
| 走路途中 | 「……腿都坐麻了。」 |
| 走到目的地 | 「就这儿吧。」 |
| 刚睡醒 | 「……唔，我睡着了？」 |

自检里有断言检查这张对应关系，并禁止把视线跟随的那两行用作随机姿势。

这些是**本地台词库**（9 组 41 句），不调用模型——它们是高频的环境音，为一句"……困了"花 token 不划算。「主动找你说话」是另一回事，那个会真的调用 DeepSeek，间隔也长得多（默认 25 分钟）。

情绪的驱动方式：系统提示词要求模型在回复**开头**输出一个 `[[mood:xxx]]` 标记，主进程边流式接收边把标记剥掉（所以气泡里永远不会看到它），再映射成上面的状态。

想调整活跃度，改 `src/renderer/behavior.js` 顶部的 `POSES` 表（概率、时长）和 `WALK_SPEED` 即可。

```
  atlas-slicer.html  在渲染进程里做 WebP 解码与像素处理（Electron 的 nativeImage 不支持 WebP）
  inspect-shot.js    调试用：裁切并放大截图，输出像素采样，用来定位界面问题
docs/
  animations.png     11 行动画总览（每帧 + 用途 + 实测动作幅度）
```

### 实现上踩过的坑

1. **渲染进程不能用 `file://`。** Chromium 会以 CORS 为由拒绝加载 `file://` 下的 ES module。因此应用注册了 `deskpet://` 自定义协议来提供页面和素材，顺带让图集同源、canvas 不被污染。
2. **`nativeImage` 解不了 WebP。** 托盘图标无法用 `nativeImage.createFromPath` 从图集裁出来，所以由 `npm run slice` 在渲染进程里裁好、导出成 PNG。
3. **每行帧数不是 8。** 实测为 `[7, 8, 8, 4, 5, 8, 6, 6, 6, 8, 8]`，行尾有空帧。若一律按 8 帧播会闪空白。`pet-spec.js` 里用的是实测值。
4. **渲染进程必须没有网络能力。** 渲染进程从不联网，所有模型调用都在主进程。CSP 里的 `connect-src 'none'` 把这件事从约定变成了保证。
5. **行名会骗人，状态映射要看实际动画。** 第 8 行叫 `review`，听起来像"安静地阅读"，实际美术是**完整的左右摇头**；第 1 行叫 `running-right`，实际是**坐着的摇摆**。两个名字各让我踩了一次坑：一次把摇头当成看书姿势（她一直在摇头），一次把走路的美术当成坐姿待机（看起来像原地走路）。`npm run slice` 会输出每一行的**逐帧像素变化量**并写入 `.qa/motion-profile.json`。现在的做法是**剪辑名按画面内容起**（`lyingRead` / `seatedShake` / `seatedNod`），并且活跃姿势必须带 `maxHoldMs` 上限——摇头动作保留下来了，但最多只演 7 秒。
6. **"她太安静了"也可能是调度问题，不是概率问题。** 原来的实现里走完一段路会把下次决策推到 24–62 秒之后，于是她**走 2.5 秒、趴一分钟**，实测趴着占约 95%。调概率没用。现在改成"定居（换 2–4 个姿势）→ 走一段 → 再定居"，并且有确定性断言：`samplePoses(6000)` 采样姿势分布，要求趴、坐两种都 ≥30%。
7. **状态名和剪辑名是两个词表，混淆会让整个窗口空白。** `thinking` 一度写成 `clip: 'daydream'`（那是状态名），而 `Animator` 的默认剪辑名还留着已删除的 `'idle'`。两者都会在**绘制第一帧**时抛错，于是渲染进程直接死掉、窗口一片空白。现在有 `validateStates()` 在启动时检查，并且 `Animator.clip` 有兜底。
8. **`loop: false` 的状态不能配循环剪辑。** overlay 的自动结束逻辑问的是"剪辑播完了吗"，而循环剪辑永远不算播完——于是 `sad` / `angry` 反应**只闪现一帧就消失**。这一条也在 `validateStates()` 里。
9. **气泡是共享资源，需要区分"闲聊"和"你问的回答"。** 她自言自语时直接复用了同一个气泡，同时覆盖了唯一一份存档——于是长篇回答被一句「……腿都坐麻了。」顶掉之后就**再也找不回来**。现在气泡带 `kind`，自言自语会主动跳过正在显示的回答，回答另有单独的存档，并且有对话记录窗口兜底。
10. **"别在我读东西的时候乱动"需要一个显式的注意力信号。** 行为引擎原本完全不知道屏幕上有没有东西，所以她会一边走开一边冒泡。现在回答显示期间给她一个 `attentionUntil` 保持期，气泡收起（或超时）即恢复。
11. **取消走动必须通知渲染进程。** 走完会发 `walk:done`，但被 `stopWalk()` 打断时原来不发——于是她会永远保持走动姿势原地摇摆。现在 `stopWalk({notify:true})` 用于所有外部取消路径。
12. **美术带了暗色 alpha 暗边。** 半透明边缘像素的 RGB 是深色（实测均值 `42,29,44`，而实体是 `183,167,185`），浅色桌面上会合成出脏灰描边。启动时做一次颜色外扩修正，alpha 不动。
13. **情绪色调必须裁剪在角色轮廓内、必须很淡、而且默认应当关闭。** 见[关于状态色调](#关于状态色调)；绘制顺序也因此必须是「先角色后特效」。
14. **透明窗口的 `setPosition` 很便宜**（实测约 1–2ms），所以走动可以逐帧移动窗口；但移动时写配置文件必须防抖。
15. **想让缩放既无级又清晰，得靠超采样而不是吸附。** 先按整数倍栅格化到离屏画布，再缩放到目标尺寸：整数倍是 1:1 搬运，非整数倍是降采样。直接吸附到整数倍会让尺寸控制变得像只有几档。
16. **视线跟随不能依赖 `mousemove`。** 鼠标一旦移出窗口，渲染进程就收不到后续移动事件，最后记录的坐标会**冻结**；如果它恰好是从窗口侧边离开的，那个坐标仍在判定半径内，她就会一直盯着那个方向不动。改成主进程用 `screen.getCursorScreenPoint()` 以 10Hz 轮询全局光标，位置与窗口边界无关，"鼠标走远了"才成为事实而不是推断。
17. **改了默认值必须配迁移。** `deepMerge(DEFAULT_SETTINGS, stored)` 用存储值覆盖默认值，所以对已存过该键的用户改默认值毫无作用；而迁移要在合并**之后**跑，版本号却必须从**原始文件**读。见[关于状态色调](#关于状态色调)。
18. **别在输入框上只留"按回车保存"这一条路。** API Key 的输入框原来只有 Enter 能保存，用户填完点「完成」就静默丢弃了，而且任何别的设置变动触发的重绘还会清空输入框。现在有显式保存按钮 + 失焦保存 + 「完成」前保存 + 保护未保存的输入。

`npm run selftest` 会启动真实应用，依次切到每个状态截图到 `.qa/states/`，并断言：思考状态不会瞬间过期、视线左右映射正确、窗口可见、走动能真的移动窗口、模型错误能被干净地报出来、图集去灰边已生效、缩放是无级的（333/400/507 都精确命中）、**情绪光晕没有溢出角色轮廓**、改大小能真的改变窗口、余额接口错误被正确处理、余额不足提醒只触发一次。

加上 `DESKPET_SELFTEST_NET=1` 还会用无效 Key 真打一次 DeepSeek，验证 HTTP + SSE 链路和余额接口。

产物：`.qa/states/*.png`（逐状态截图）、`.qa/settings-window.png` 与 `-2.png`（设置页上下两部分）、`.qa/history-window.png`、`.qa/low-balance.png`、`.qa/selftest.json`（报告）。

```bash
electron tools/inspect-shot.js <图片路径> .qa/inspect
```

调试时渲染进程暴露了 `window.__deskpet`：可以 `__deskpet.setBase('sleepy')`、`__deskpet.setOverlay('happy')`、`__deskpet.setLook(4)`、`__deskpet.setSize(600)`、`__deskpet.measureBackground()`、`__deskpet.info` 等。

设置与对话记忆默认存在系统用户数据目录（可用环境变量 `DESKPET_DATA_DIR` 覆盖，方便做便携或隔离运行）。

## 常见问题

**填了 API Key 却一直提示要填。** 确认点过「保存」（回车或点「完成」也会保存）。保存成功后输入框下方会显示「已保存，并使用系统密钥库加密存储」。如果仍然不行，点「测试连接」看具体报错。

**她回答问题太短 / 我想要她认真帮忙。** 那是闲聊模式的人设约束（1~3 句）。输入 **`/work`** 或打开设置里的「工作模式」，她会解除长度限制、允许 Markdown 和代码，并把准确性放在语气前面。输入 `/pet` 可以切回去。

**回答还没看完就没了。** 现在不会了：长回答按字数停留（最长 60 秒），期间她不会走开也不会插话，回答也另存了一份。点她一下可以把最后一条回答原样调回来；更早的内容在托盘菜单 →「对话记录…」。

**她一直不说话 / 提示 API Key 被拒绝。** 检查 Key 是否复制完整、账户是否有余额（HTTP 402 会提示余额不足）。设置页点「测试连接」能直接看到原因。

**她挡住我点别的窗口。** 打开「鼠标穿透」（默认开启）。开启后只有她本人、气泡和输入框会接收鼠标，其余透明区域直接放行到桌面。

**她在别的窗口上面，但我想让她下去。** 托盘菜单或右键菜单里关掉「总在最前」。

**怎么让她别乱走。** 右键菜单 → 自主行为 → 关掉「随机走动」。想全关就取消「自主行为」。

**她一直摇头 / 原地摇摆很久。** 有两个来源，都已修掉：(1) 走动的精灵行是"坐着左右摇摆"，旧版一次走动可能持续近 20 秒；(2) 「看书」状态原来用的第 8 行美术本身就是**左右摇头**动画，而她大部分时间都在这个状态。现在第 8 行最多只演 7 秒，且只作为短暂姿势。如果还想更静，右键菜单 → 自主行为 → 关掉「随机走动」。

**她一直盯着一个方向不动。** 这是旧版本的 bug（鼠标移出窗口后视线卡住）。现在视线基于主进程轮询的全局光标位置，鼠标离开约 300px 就会放开；如果仍然如此，检查设置里「视线跟随鼠标」是否开着，以及显示器是否用了 Wayland（该平台上系统光标位置可能不可用，会退回旧行为）。

**她整个人像被重新上色了。** 检查设置里的「状态色调」。**默认是关的**，如果开着而你觉得偏黄，关掉即可——粒子特效不受影响。

> 如果你是从旧版本升级上来的：旧版把这个开关默认设成开，并且**已经把你当时的配置存进了文件**。现在的版本会在启动时自动迁移把它关掉，不用手动处理。

**边缘还是有点灰 / 我想要更锐。** 确认设置里「去除边缘灰边」开着。渲染方式想更硬朗就选「硬边像素」，但正常建议用默认的超采样模式。如果**她周围整片区域发灰**，那不是边缘问题——先确认你用的是不是最新版本（旧版有个光晕会溢出到背景）。

**大小调不动 / 只有几档。** 最新版是无级的。如果拖滑块没反应，可能是窗口已经顶到屏幕高度上限，`fitSpriteSize` 会把她压回可用空间。

**余额一直显示「尚未查询」。** 需要先填 API Key。填完后设置页点「立即查询」；如果报错，错误信息会直接显示在余额卡片里（常见的 401 是 Key 无效）。

**换台电脑后开机自启失效。** 开机自启写的是当前 `electron.exe` 的绝对路径。项目移动过位置，就到设置里关掉再打开一次「开机自动启动」。

**能换成别的角色吗。** 能。把 `assets/citlali/` 换成任意符合 Awesome Codex Pet v2 格式的包（1536×2288 WebP，8×11，单帧 192×208），再改 `src/preload/preload.js` 里的 `atlasUrl`。并按 `npm run slice` 输出的实测帧数更新 `src/shared/pet-spec.js` 里的 `CLIPS`。
